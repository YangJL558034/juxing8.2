# 员工数据部署与备份

生产部署将 CRM_DATABASE_PATH 设置为持久化磁盘中的数据库路径。未设置时保留原路径，避免升级后切换到空数据库。已有生产环境不得直接更换路径；先停止写入、备份，将完整备份迁入目标磁盘，再设置路径启动。

运行 `pnpm exec tsx scripts/backup-database.ts` 创建包含 WAL 中已提交数据的 SQLite 一致性备份，并进行完整性检查。可设置 CRM_BACKUP_DIR 指向独立备份磁盘。不要只复制正在运行的 crm.db，也不要将数据库、WAL 或备份文件提交到公开仓库。

上传附件所在的 public/uploads 也需要持久化并单独备份。更新程序不能覆盖数据库或上传目录。应定期把数据库与附件备份到另一台设备，并在隔离环境做恢复测试。

员工登录仍兼容姓名和身份证首次核验；核验后使用 HttpOnly 会话校验头像上传与通知已读请求。会话保存在数据库，30 天到期，退出时撤销当前设备会话。增强首次认证为短信验证码或密码属于下一步认证升级，当前没有接入短信服务。

旧头像可在原设备打开新版时迁移到服务器。旧版已读缓存没有绑定员工身份，不自动迁移，以免错误标记其他员工通知；新版本保存后的已读状态跨设备同步。
